# Acceptance evidence

Current-instance validation: production frontend build and API, SQLite server persistence, and an actual separate scheduler worker. This is not a deployed URL or a new-task restoration check.

Final results: `npm run build` passed; `npm test` ran 20 tests, all passed, none skipped; `npm run test:browser` ran 10 Chromium tests, all passed, none skipped. Four backend tests exercise the model adapter through explicit mocked transport or validation inputs. They do not establish live provider availability or summary fidelity.

The install script was executed with frozen npm lockfile installation, type checking, production build and idempotent source seeding. Startup was exercised across separate tool calls and a managed restart. A sandbox restriction prevents reading another process's /proc cwd; the final startup script verifies its own managed process identity using absolute entry paths and owner through `ps`. It starts no duplicate healthy managed service. Readiness checks require both API success and a recent independent-worker heartbeat. A functional production sample request verified substantive exact source content, after which its isolated validation guest was deleted.

No live model call, real email/push notification, public/private hosted deployment, Docker image build, fresh cloud task restoration, worldwide territorial clearance or independent editorial audit has been verified. The model adapter uses structured source references, exact-quote checking, conservative quantity rejection, bounded input/output, timeout, rate limits and pending editorial-review labels. Valid citations alone do not prove fidelity. All optional AI controls remain unavailable in this instance because no key is configured; failures preserve the prior edition. Scheduled editions use prepared content.

Sites is not exposed here. The prepared environment draft contains the tested install/start instructions, repository mount, Gutenberg network additions, optional model configuration and the secure model-key requirement. Saving that draft is not applying it or publishing a snapshot. The user must review/save environment settings and publish the environment; public app hosting requires a supported persistent server and supervised worker.
